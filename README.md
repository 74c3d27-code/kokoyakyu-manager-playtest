# 高校野球監督ゲーム 3年間プレイ検証版 v0.2.0

高校野球監督ゲームと、将来の野球人生ゲームで共有する共通エンジンの開発版です。
この版では、架空県16校のうち1校を選び、**1週間ずつ合計156週、3年間**を実際に進められます。

## 入口

ローカル起動後、またはCloudflare Pages公開後に次の3画面を使います。

```text
/           開発版の入口
/manager/   3年間監督プレイ
/lab/       シミュレーション検証室
```

## 3年間監督プレイでできること

- 16校から監督校を選択
- 1年52週、合計3年間を週単位で進行
- チーム練習の重点を選択
  - 総合、ミート、長打、走力、守備、投手、回復
- 練習負荷を軽め、標準、強めから選択
- 最大3人に個人重点または守備位置転向を指定
- 先発候補と投手運用方針を指定
  - エース優先、標準、健康優先
- 春、夏、秋の16校県大会
- 春ベスト4を夏の4シードへ反映
- 9回制、DH、コールド、延長タイブレーク
- 直近7日間500球の規則上限
- スタミナ、投球数、疲労、連投を分けた健康リスク
- 夏終了後の3年生引退と秋の新チーム
- 秋上位2校の簡易地区大会評価
- 秋成績と試合内容による簡易選抜選考
- 中学生候補12人から最大3人へ関心表明
- 公立校の地域・学力条件、選手希望とのマッチ度
- 年度末の卒業、進級、新入生加入
- ブラウザ内への自動保存
- セーブJSONの書き出し・読み込み
- 3年間の大会成績と年度履歴

試合は基本的に自動処理です。現段階では、一球ごとの配球や重要局面への手動介入はありません。

## シミュレーション検証室でできること

- 1～100年、複数反復の自動処理
- 最大5,000シーズンの一括検証
- 平均得点、コールド率、延長率
- 夏シード校の勝率
- 公立・私立の優勝比率
- 学校別優勝回数
- 投手の高リスク登板、危険登板、故障
- 能力分布と長期インフレ
- 同じ乱数シードによる結果再現
- 結果JSONの書き出し

## 実装している基本ルール

- 9回制
- DHあり
- 10回から無死一・二塁のタイブレーク
- 県大会は5回10点差、7回7点差でコールド
- 雨天中断、雨天順延、継続試合なし
- 登録や試合処理は架空県16校向けに簡略化
- 直近7日間の公式戦500球を規則上限とする
- 規則上の登板可否と健康リスクを別管理する

## 選手能力と成長

野手能力はミート、長打、走力、守備、肩、投手能力は球威、制球、変化球、スタミナです。
各能力には現在値、到達しやすい上限、最終上限、成長適性があります。

高校監督ゲームでは、早熟・標準・晩成という明示区分を使っていません。高校生は基本的に全員を成長期として扱い、選手差は次で表現します。

- 能力ごとの潜在上限
- 能力ごとの成長適性
- 現在値と上限の距離
- 学校の設備・指導力
- 練習方針と負荷
- 疲労・故障
- 守備位置適性の習得難度

捕手、遊撃手、投手への転向は難しく、投手転向は一定の投手適性を得るまで実戦候補になりません。

## ローカル起動

Node.js 22を使用します。

```bash
npm install
npm test
npm run dev
```

ブラウザで次を開きます。

```text
http://localhost:4173
```

停止するときは、ターミナル上で `Ctrl + C` を押します。
Windowsでは `START_LOCAL_WINDOWS.bat`、macOS/Linuxでは `start-local.sh` も利用できます。

## GitHubとCloudflare Pages

GitHubへソース一式を置き、Cloudflare Pagesで次を設定します。

```text
Production branch: main
Framework preset: None
Build command: npm run build
Build output directory: dist
Root directory: 空欄
```

`.node-version` に `22` を入れているため、Node.jsのバージョンをソース側で固定しています。
サーバー、データベース、Workers、D1、KVは現段階では不要です。

詳しい画面操作は次をご覧ください。

- `docs/BEGINNER_GUIDE.md`
- `docs/BEGINNER_GUIDE.html`
- `docs/CLOUDFLARE_PAGES.md`

## GitHub Actions

`.github/workflows/ci.yml` が、GitHubへのpushとPull Requestで次を実行します。

```text
npm install
npm run typecheck
npm test
```

GitHubの `Actions` 画面で緑色のチェックになれば、自動検査は成功です。

## 検証の目的

完成品ではなく、次の問いを確かめる版です。

1. 3年間を一週ずつ進めてもテンポが重くないか
2. 練習方針と個人育成に意味があるか
3. 投手を休ませる判断が試合結果と翌戦へ影響するか
4. 春の結果と夏シードに価値があるか
5. 夏敗退後も秋の新チームを進めたくなるか
6. 公立・私立、強豪・弱小で違う遊び方になるか
7. スカウトと選抜選考に納得感があるか
8. 3年生卒業後の戦力変化が次年度への動機になるか
