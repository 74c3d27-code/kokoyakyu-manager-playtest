高校野球監督ゲーム v0.3.0／Node.js不要版

先に結論

今回の版では、Cloudflareにソースコードを変換させません。完成済みのHTML・CSS・JavaScriptをそのまま公開します。

設定値は次の4つです。

設定値
Framework presetNone
Root directorydeploy
Build commandexit 0
Build output directorypublic

これにより、Cloudflareはリポジトリ直下の古いpackage.jsonを見ず、deploy/public/だけをWebサイトとして公開します。

1. 今回のエラーについて

添付画像では、次のところまでは成功しています。

  • Initializing
  • Cloning
  • Installing
  • bun install

その後、Executing user build command: npm run buildの直後にBuildingが失敗しています。ただし、画像には実際の赤いエラー本文が写っていないため、TypeScript、ファイル位置、権限など、どれが直接原因だったかは断定できません。

v0.3.0では原因調査を待たず、次の処理を丸ごと不要にしました。

  • npm install
  • bun install
  • npm run build
  • Node.js
  • TypeScriptコンパイル

ブラウザ用ファイルはすでにdeploy/public/へ完成した状態で入っています。

2. ZIPを展開する

  1. kokoyakyu-manager-nobuild-v0.3.0.zipを右クリックします。
  2. 「すべて展開」を選びます。
  3. 展開後のフォルダを開きます。
  4. 次が見えることを確認します。
deploy
README.md
START_HERE.txt
CLOUDFLARE_NO_BUILD_GUIDE.html
MOBILE_TEST_CHECKLIST.txt

deployの中は次の構造です。

deploy/
└─ public/
   ├─ index.html
   ├─ manager/
   ├─ lab/
   ├─ apps/
   ├─ packages/
   ├─ guide/
   └─ VERSION.txt

3. GitHubへ追加する

方法A：GitHub Desktopを使う方法

継続更新にはこちらが安全です。

  1. GitHub Desktopを起動します。
  2. 対象リポジトリを開きます。
  3. Repository → Show in Explorerで作業フォルダを開きます。
  4. 今回のZIPから展開したdeployフォルダを、リポジトリ直下へコピーします。
  5. README.mdなども必要に応じて上書きします。
  6. GitHub Desktopへ戻ります。
  7. 左側のChangesに追加・変更ファイルが表示されます。
  8. Summaryへ次を入力します。
v0.3.0 no-build mobile release
  1. Commit to mainを押します。
  2. Push originを押します。

方法B：GitHubのWeb画面から追加する方法

  1. GitHubで対象リポジトリを開きます。
  2. Add file → Upload filesを押します。
  3. 展開したdeployフォルダをアップロード欄へドラッグします。
  4. 最終的にGitHub上で次の場所が見えることを確認します。
deploy/public/index.html
  1. コミットメッセージへ次を入力します。
v0.3.0 no-build mobile release
  1. Commit changesを押します。

古いファイルについて

以前の次のファイルがリポジトリに残っていても、ひとまず削除しなくて構いません。

package.json
.node-version
apps
packages
scripts
tsconfig.json

CloudflareのRoot directoryをdeployへ変更するため、それらは公開処理で使用されなくなります。

4. Cloudflareの設定を変更する

  1. Cloudflareへログインします。
  2. Workers & Pagesを開きます。
  3. 対象の高校野球プロジェクトを開きます。
  4. 上部のSettingsを押します。
  5. Builds & deploymentsまたはBuild configurationに相当する項目を開きます。
  6. Edit configurationを押します。
  7. 次の値へ変更します。
項目入力値
Framework presetNone
Production branchmain
Root directorydeploy
Build commandexit 0
Build output directorypublic
Build variablesなし
  1. 保存します。

大切な点

Root directoryは空欄ではなく、必ず次です。

deploy

Build output directoryは次です。

public

Cloudflareから見ると、公開対象は実質的に次の場所になります。

deploy/public

5. 新しいDeploymentを確認する

GitHubへコミットを送ると、Cloudflare側で新しいDeploymentが始まります。

成功時は次の順で緑になります。

Initializing
Cloning
Building
Deploying

今回の版では、ログ中に次を実行させる必要はありません。

npm run build
bun install
npm install

Build commandはexit 0だけです。

新しいDeploymentが自動で始まらない場合は、設定保存後にGitHubでREADMEへ空白を一つ加えるなど、小さなコミットを送ってください。

6. 公開確認

発行されたpages.devのURLで、次を順に開きます。

https://プロジェクト名.pages.dev/
https://プロジェクト名.pages.dev/manager/
https://プロジェクト名.pages.dev/lab/
https://プロジェクト名.pages.dev/guide/
https://プロジェクト名.pages.dev/VERSION.txt

VERSION.txtに次が表示されれば更新済みです。

kokoyakyu-manager-playtest v0.3.0

404になる場合

GitHubで次のファイル位置を確認します。

deploy/public/index.html

Cloudflare設定を確認します。

Root directory: deploy
Build output directory: public

古い画面が残る場合

  1. ブラウザのページを再読込します。
  2. スマートフォンではタブを完全に閉じて開き直します。
  3. それでも古い場合は、プライベートブラウズでVERSION.txtを開きます。

7. スマートフォン画面

監督ゲームでは、幅760px以下でスマートフォン向け表示へ切り替わります。

下部ナビゲーション

画面下に次の6タブが固定されます。

週　選　育　大　勧　保

意味は次のとおりです。

表示画面
週ホーム・週間状況
選選手一覧
育育成・投手起用
大大会・年度成績
勧スカウト
保保存・説明

「今週を進める」ボタンは、そのナビゲーションの一段上に固定されます。

選手一覧

PCでは横長の表、スマートフォンでは選手ごとのカードになります。

カードでは次を確認できます。

  • 学年と守備位置
  • 打撃5能力
  • 投手候補の投手4能力
  • 守備位置適性
  • 疲労と故障リスク
  • 伸びしろ

画面回転

縦向きと横向きの両方で操作できます。横向きでは下部ナビゲーションと進行ボタンを少し低くし、表示領域を確保します。

8. セーブについて

セーブは毎週、ブラウザ内へ自動保存されます。

ただし、次の場合は同じセーブが見えません。

  • 別のスマートフォン
  • 別のブラウザ
  • 別のドメイン
  • ブラウザのサイトデータを削除した場合

端末を移すときは、ゲーム内の保 → JSONバックアップを使います。

  1. 元端末で「セーブを書き出す」
  2. JSONファイルを新端末へ送る
  3. 新端末で「セーブを読み込む」

9. 最初の検証手順

  1. 公立中堅校を選びます。
  2. 世界シードを変更せず開始します。
  3. 数週間は「総合・標準」で進めます。
  4. 育で投手運用を健康優先へ変更します。
  5. 遊撃手または捕手へのコンバートを指定します。
  6. 春大会ベスト4と夏シードを確認します。
  7. 夏敗退後の新チームを確認します。
  8. 秋大会と選抜評価を確認します。
  9. 勧で候補を最大3人選びます。
  10. 年度末の卒業、進級、新入生を確認します。
  11. 3年間、156週を完走します。
  12. 保からセーブJSONを書き出します。

スマートフォンの確認項目はMOBILE_TEST_CHECKLIST.txtをご利用ください。
